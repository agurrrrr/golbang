### 분류

기동 로그: `scheduler budget n_batch=2048 n_ubatch=2048 prefill_max=2048 decode_max=1`.

`IterationBudget::for_context(..., n_parallel=1)` 가 `decode_max = n_parallel` 로 두고,
`BatchBuilder` 가 **드래프트 토큰까지** 그 예산에 센다. pending 1개를 넣은 뒤
초안이 잘려 `verify_and_emit` 이 한 번도 안 돈다 → `/metrics` draft 0.

~10 t/s 는 “스펙큘 없는 천장”과 같다. 커널이 아니라 플래너 버그.

커밋 `c6400b7` `fix(spec): count decode_max as slots so drafts verify`.

## 고친 뒤 1 — 드래프트는 켜짐, 검증 스냅샷이 무거움

| 밴드 | golbang post1 | draft | snapshot |
|------|--------------:|------:|---------:|
| smoke16 | 21.70 t/s | 10/10 mean 3.50 | ~150 MiB/step |
| para84 | 18.13 t/s | 38/38 mean 2.90 | 688 ms / req |
| mid200 | 16.42 t/s | 84/96 (87.5%) | 1.8 s / req |

`n_rs_seq=1` 이라 거절 3토큰을 `seq_rm` 으로 못 되감고, 매 스텝 PARTIAL_ONLY ~150 MiB를 복사했다.
llama-server는 `n_rs_seq = spec n_max` (`need_n_rs_seq`) 이라 이 복사가 없다.

커밋 `ba56d0c` `fix(spec): set n_rs_seq to MTP n_max so verify skips 150MiB snapshots`.
