# P8 — 호스트 접두 스냅샷: 에이전트 대화의 prefill 단축

> 기록: 2026-08-31. 이슈 #88(A·B·C)와 후속 #89~#94. 저널 확인은 `golbang-deepseek`
> (MI50)와 `golbang-qwen38` (MI50)의 `RUST_LOG=info` systemd 저널이다.
> 코드는 Rust 스케줄러만 건드렸고 GPU 커널 diff는 0이다.

## 배경: 왜 prefill이 문제인가

에이전트(툴 루프)는 턴마다 지금까지의 프롬프트를 누적해서 다시 보낸다. 골뱅이가 매 턴을
0부터 prefill하면 30k~70k 토큰을 몇 분씩 다시 계산한다. P5가 슬롯 안에서 하던
"같은 대화 2턴째 접미만"을, P8은 **슬롯 밖·체인·워터마크 이후**로 늘린다.

- 바탕 API: `Engine::seq_state_get` / `seq_state_set` (`llama_state_seq_*_ext`, `PARTIAL_ONLY`).
  P5가 이미 쓰던 것이다. 새 FFI는 없다.
- **안 쓰는 것**: `llama_memory_seq_cp` 교차 슬롯 복사(P3가 스파이크로 기각), GPU KV 페이지
  참조 카운트 radix 트리(llama.cpp unified KV에는 그 참조가 없어 paged KV 엔진을 새로
  만들어야 한다). SGLang RadixAttention의 **효용**(공통 접두를 요청이 끝내도 살림)만 가져온다.
- 제약: Qwen hybrid `seq_rm`은 37k 시퀀스를 12545로 자를 수 없다. 그래서 복원은
  **그 길이로 미리 찍힌** 덤프만 가능하다. 스냅샷은 불투명 전량 덤프라 델타 합성이 없다.

## 정직한 조건과 한계

P8은 모든 전량 프리필을 없애지 않는다. 아래는 저널에서 실제로 확인된 갈림이다.

1. **빈 슬롯 복원(B)은 `n_parallel=2`에서 열린다.** `n_parallel=1`이면 빈 슬롯이 없어
   같은 슬롯 affinity(P8-A)만 히트하고 `restore_host_snapshot`까지 내려가지 않는다.
2. **승격은 첫 긴 prefill이 스텁 창 경계에 정확히 착지해야 남는다.**
   `is_host_stub_boundary`는 `n_past`가 6144/8192/12288… 에 떨어질 때만 참이다.
   Qwen 생산은 `n_batch=n_ubatch=2048`이라 8192에 착지해 승격이 남았다. DeepSeek 유닛은
   llama-server와 맞춘 `-b 5800`이라 `n_past`가 0→5800→10401로 뛰어 스텁 경계를 건너뛰고,
   `host prefix snapshot promoted`가 0회였다.
3. **`tools`를 빼면 공통 접두가 창 밖으로 떨어진다.** compact 요청이 `tools` 배열을
   빼면 도구 스키마 위치(생산 실측 LCP 약 3787) 이후 토큰이 전부 바뀐다. 3787은 스텁 창
   (6144–16384)보다 짧아 체인·스토 모두 미스이고, 45k~52k를 전량으로 다시 돌렸다.
4. **워터마크 생존(C)의 라이브 확인은 아직이다.** 코드와 FakeSeqKv 단위 테스트로 잠겨
   있으나, 관측한 생산 창에서 85% 워터마크가 발화하지 않아
   `retained prefix kv released; host anchors kept`가 0회였다. 두 세션이 동시에 약 60k씩
   점유해야 이르지만, 그 조건을 만들지 못했다.
5. **호스트 RAM은 상한으로 누른다.** `HOST_RAM_CAP`(2 GiB)이 두 슬롯 체인을 같이 줄여,
   한 슬롯의 이전 라운드 끝이 다른 슬롯 저장 때문에 중간 장으로 사라질 수 있다. 최신 앵커는
   남는다.

## 저널 판별 문구

| 로그 | 의미 |
|------|------|
| `prefix restored from checkpoint reuse_len=… ckpt_n=…` | P8-A 체인 복원 |
| `host prefix snapshot promoted n_tokens=… bytes=…` | P8-B 스토 승격 |
| `host snapshot restored …` / `host snapshot miss lcp=… store_ns=…` | P8-B 빈 슬롯 복원 / 미스 |
| `retained prefix kv released; host anchors kept` | P8-C 워터마크 GPU만 해제 |
| `prefix chain not usable; full prefill` | 복원 실패 → 전량 폴백 (피해야 할 신호) |
