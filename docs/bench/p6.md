# P6 벤치 기록 — rocprof 커널 순위

> 이 파일은 `docs/bench/p6.md` (P6 지시서 §4.1 / §4.2 / 완료 기준 참조).
> 결과는 **사후에 목표치를 맞추지 말고 있는 그대로** 기록한다.
> 측정일: 2026-08-14. **HIP C++ 패치 없음. Rust GPU 커널 0줄.**

## 결론 (지시서 §4.2 중단)

프로파일이 **특정 GPU 커널을 지목하지 않는다.** 커널 diff는 0이다.

P5 이후의 실제 경로(suffix prefill + decode)에서 벽시계의 약 70–80%는
GPU 커널이 아니라 **호스트 / CPU MoE** (`--n-cpu-moe 32`, `graph splits = 66` at bs=1)다.
요청 구간의 PCIe `hipMemcpy`는 decode에서 span의 0.3%다.

전량 4k prefill은 GPU 커널 66% + H2D 25%이지만, 그 커널도
rocBLAS F16 패밀리(~49%) · `flash_attn_tile`(~22%) · dequant(~13%)로 갈라진다.
하나 고쳐도 tok/s가 거의 안 움직인다.

`GGML_HIP_MMQ_MFMA=ON`으로 빌드돼 있으나, `ggml_cuda_should_use_mmq`가
**gfx906(Vega20)에서 항상 false**다. 트레이스에 `mul_mat_q`는 0건.

P4(#27) gate 문장 "프로파일이 특정 커널을 지목"은 **실패**.

## 0. P5 선행

생산 유닛에 `--n-rs-seq 1`이 있다. 이번 prefix 세션:

기본 표는 이 2턴째(suffix)와 decode다. 전량 4k는 비교용으로 따로 적는다.

## 1. 요청 구간 예산 (로드 제외)

타임스탬프 갭 200 ms로 버스트를 나눈 뒤, 마지막(요청) 그룹만.

| 구간 | wall / span | GPU 커널 합 | 요청 H2D+D2H | 호스트 공백 | 호스트 비율 |
|------|------------:|------------:|-------------:|------------:|------------:|
| 전량 prefill 4429 tok, `max_tokens=1` | 55.20 s | 36.77 s (66.6%) | 13.85 s (25.1%) | 4.59 s | 8.3% |
| prefix-hit suffix 23 tok | 2.60 s | 0.51 s (19.8%) | 0.009 s (0.3%) | 2.08 s | **79.9%** |
| decode 120 tok (짧은 프롬프트 26 tok 포함) | 19.54 s | 6.09 s (31.2%) | 0.059 s (0.3%) | 13.39 s | **68.5%** |

호스트 공백 = span − kernel_sum − copy_sum. 단일 스트림이라 커널은 거의 겹치지 않는다.

decode 120 tok 서버 타이밍: prompt 26 tok / 3.19 s, predicted **120 tok / 16.69 s = 7.19 tok/s**.
전량 prefill: 4429 tok / 55.56 s = **79.72 tok/s** (비프로파일 대화 ~77과 동급, rocprof 오버헤드 작음).

모델 로드 H2D는 세 세션 모두 ~2.16 s / 1459회. raw domain stats의 "memcpy 30–64%"는 이 로드분이다. 요청 구간이 아니다.

## 4. decode (≥50 토큰) — 커널 순위

프롬프트 "80까지의 정수를…" `max_tokens=120`. 생성 120토큰(reasoning), 16.69 s, **7.19 tok/s**.

요청 구간: 커널 6.09 s (31.2%), 복사 **0.059 s (0.3%)**, **호스트 13.39 s (68.5%)**.

| 순위 | 이름 | 호출 | 총 ms | 커널% |

| 1 | `mul_mat_vec_q<Q8_0, ncols=1>` | 37723 | 1225 | 20.10 |
| 2 | `mul_mat_vec_f` | 12853 | 331 | 5.44 |
| 3 | `mul_mat_vec_q<IQ2_XXS, ncols=1>` | 3262 | 293 | 4.81 |
| 4 | `k_get_rows` | 53040 | 261 | 4.29 |

| 6 | `mul_mat_vec_q<Q5_K, ncols=1>` | 14994 | 235 | 3.86 |

32개 MoE 레이어는 CPU에서 돌아가고, 그래프가 토큰마다 66번 쪼개진다.

## 5. `GGML_HIP_MMQ_MFMA` 재확인

빌드 캐시: `GGML_HIP_MMQ_MFMA:BOOL=ON`. `libggml-hip.so`에 `mul_mat_q` 심볼과 `flash_attn` 타일은 있다.

런타임 (`llama.cpp` `ggml/src/ggml-cuda/mmq.cu`):

```cpp
// gfx906 (Vega 20 / MI50): the dp4a MMQ path is unstable and can hang or
// crash the HIP runtime for some quantization types (observed with
// GGML_TYPE_IQ2_S). Fall back to dequantization + (hip/roc)BLAS instead.
if (cc == GGML_CUDA_CC_VEGA20) {
    return false;
}
```

`amd_mfma_available`은 `GGML_CUDA_CC_IS_CDNA` (gfx908+)만 true.
llama.cpp는 MI50을 **GCN Vega20**으로 분류하고, MFMA MMQ는 CDNA1(MI100)부터다.
플래그를 켜도 gfx906에서는 dequant + rocBLAS만 탄다. 트레이스가 그걸 확인했다.

이 가드를 푸는 것은 "지목된 커널 1개"가 아니라 디스패치 정책 변경이고,
주석에 적힌 HIP hang 경로다. P6에서 하지 않는다.

## 6. 중단 사유 (지시서 §4.2에 해당)

1. **1위가 GPU 커널이 아니다.** P5 이후 경로(suffix·decode)의 1위는 호스트/CPU MoE다.
2. **1위가 `n_cpu_moe=32` 쪽이다.** `graph splits = 66` (bs=1). 요청 구간 memcpy는 decode 0.3%.
3. **전량 prefill조차 한 커널이 큰 몫을 못 가진다.** flash_attn 22% vs rocBLAS 타일 21% vs dequant 13%. 패밀리로 묶어도 그다음이 CPU/복사다.
4. 후보로 적어 둔 이름:
   - `vllm-gfx906` attention tiling — decode 커널의 2.8%, suffix의 3.8%. 지목 실패.
   - `GGML_HIP_MMQ_MFMA` — 컴파일만 됐고 런타임 0건. Vega20 가드.

커널 패치 금지. Rust `#[amdgpu_global]` 0줄.

## 7. P4(#27) gate

지시서: "P6 rocprof가 병목을 오케스트레이션이 아니라 **특정 커널**로 지목한다."

이번 결과로는 지목하지 않았다. **P4를 열지 않는다.**
HIP로 고친 커널도 없으므로, 소유권용 Rust 재작성 대상도 없다.

다음에 P4를 다시 보려면 `n_cpu_moe`를 줄이거나 expert를 GPU에 넣는 쪽이 먼저다.
그건 32 GiB VRAM 한도(지금 ~31.6 GiB)와 충돌한다.

## 함정

- `rocprofv3 --attach`는 이미 HIP을 초기화한 `golbang-server`에서 커널 CSV를 못 남긴다. wrap-from-start만 유효.
- wrap-from-start의 `*_stats.csv` / domain %는 **모델 로드 H2D ~2.16 s**를 포함한다. 반드시 타임스탬프로 요청 구간을 잘라라.
- 짧은 decode(23 tok) raw stats는 memcpy 64%로 보인다. 로드를 빼면 0.3%다.
- prefix turn1→turn2 간격이 200 ms보다 짧아 버스트가 붙는다. wall 시간으로 뒤를 잘라라.
- sclk sysfs에 `8`을 써도 유휴 때는 level 0으로 보인다. 부하 중에 1725 MHz `*`를 확인했다.
- 생산 `golbang-deepseek.service`는 프로파일 동안 중지했다. 끝나면 다시 올린다.
