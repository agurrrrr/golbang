# P4 — (장기·선택) 순수 Rust GPU 커널 점진 재작성

> **이슈:** #21 · **선행:** P3 · **성격:** **선택 사항.** 착수 여부를 사전에 결정하고 시작한다.
> 기준 ⑤("컴퓨트도 Rust")의 이상에 가장 가까워지는 단계이지만, 공수가 크고 ROI가 불확실하므로
> **프로파일링 데이터가 있을 때만** 착수한다.

---

## 1. 목표

hot-path GPU 커널을 Rust+HIP로 **점진적으로** 재작성해 FFI(ggml-hip) 의존을 줄인다.
한 번에 전부 바꾸지 않고, 프로파일링으로 지목된 특정 커널부터 하나씩 치환한다.

**완료 기준:** 특정 커널이 Rust 구현으로 치환되고, **성능 회귀가 없음**을 측정으로 입증한다.

---

## 2. 배경 / 근거

- 현재 구조는 GPU 연산을 gfx906 빌드된 `ggml-hip`에 위임한다. 이는 검증된 커널을 쓰는 현실적 선택이다.
- 다만 기준 ⑤의 이상(서빙+컴퓨트 모두 Rust)을 완전히 채우려면 hot-path를 Rust로 옮겨야 한다.
- **주의:** gfx906(CDNA, Vega 20)용 MFMA 커널을 Rust로 처음부터 짜는 것은 수개월 단위 공수가 될 수 있다.
  그래서 "전면 재작성"이 아니라 **"hot-path 점진 치환"** 전략을 취한다.

---

## 3. 착수 전제 (gate)

다음이 충족될 때만 착수한다:
- [ ] P3의 벤치/프로파일링으로 **어느 커널이 병목인지** 데이터가 있다.
- [ ] `hip-sys` / `rocm-rs` 등 Rust→HIP 바인딩의 **성숙도를 재평가**했다.
- [ ] 해당 커널을 Rust로 치환했을 때의 **기대 이득이 공수를 정당화**한다.

---

## 5. 단계별 작업

### 5.1 대상 선정
- [ ] 프로파일링으로 hot-path 특정 (후보: GEMM / attention / sampling).
- [ ] 하나의 커널만 골라 범위를 한정.

### 5.2 Rust→HIP 경로 확정
- [ ] `hip-sys`/`rocm-rs` 등 현재 성숙도 조사. gfx906 코드젠 지원 여부가 관건.
- [ ] 불성숙하면: Rust에서 HIP 런타임 API만 호출하고 커널은 HIP C++로 두는 중간안도 검토.

### 5.3 커널 구현 + 치환
- [ ] 선택한 커널을 Rust로 구현. 기존 ggml-hip 커널과 **수치 일치** 확인.
- [ ] feature flag로 Rust 커널 ↔ 기존 FFI 커널을 전환 가능하게.

### 5.4 회귀 검증
- [ ] 치환 전후 동일 벤치로 성능 비교. 회귀 없어야 채택.
- [ ] 정확도(출력 로짓/토큰) 일치 확인.

---

## 6. 완료 기준 (Definition of Done)

- [ ] 선택한 커널이 Rust 구현으로 치환됨
- [ ] 출력 정확도 일치
- [ ] 성능 회귀 없음(측정)
- [ ] 산출물 커밋

---

## 7. 리스크 & 완화

| 리스크 | 영향 | 완화 |
|--------|------|------|
| Rust→HIP gfx906 코드젠 미지원 | 커널 작성 불가 | 착수 전 성숙도 조사로 gate. 안 되면 커널은 HIP C++ 유지 + Rust는 런타임만 |
| 성능 회귀 | 채택 불가 | feature flag로 즉시 롤백 가능하게. 회귀 시 FFI 유지 |
| 공수 폭증 | 일정 리스크 | "한 커널씩" 점진 전략 엄수. 전면 재작성 금지 |
