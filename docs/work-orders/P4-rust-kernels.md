# P4 — (장기·선택) 순수 Rust GPU 커널 점진 재작성

> **이슈:** #27 · **선행:** P3 · **성격:** **선택 사항.** 아래 gate를 모두 통과하기 전에는 착수하지 않는다.
> 기준 ⑤("컴퓨트도 Rust")의 이상에 가장 가까워지는 단계이지만, 공수가 크고 ROI가 불확실하다.

---

## 1. 목표

hot-path GPU 커널을 Rust+HIP로 **점진적으로** 재작성해 FFI(ggml-hip) 의존을 줄인다.
한 번에 전부 바꾸지 않고, 프로파일링으로 지목된 특정 커널부터 하나씩 치환한다.

**완료 기준:** 특정 커널이 Rust 구현으로 치환되고, **성능 회귀가 없음**을 측정으로 입증한다.

---

## 2. 배경 / 근거

- P0~P3는 GPU 연산을 gfx906 빌드된 `ggml-hip`에 위임한다. 검증된 커널을 쓰는 현실적 선택이다.
- "순수 Rust로 gfx906 커널 작성은 불가능"은 **과장**이다.
  - `hip-sys` 0.1.1은 런타임 바인딩이며 device function은 실패한다.
  - `rocm-rs` 0.5.2는 `rocm_kernel_macros`의 `#[amdgpu_global]`로 Rust GPU 커널 경로가 있다.
  - 다만 **gfx906/CDNA 코드젠과 rocBLAS급 최적화 커널은 미검증**이다.
- 정확한 문장: 프레임워크는 있으나 gfx906에서 쓸 만한 커널인지는 모른다. 그래서 P0~P3는 FFI, P4에서 재평가한다.

---

## 3. 착수 전제 (gate) — 전부 충족 전에 시작하지 않음

- [ ] **P0~P3가 완료**되어 있다. 그 전에는 착수하지 않는다.
- [ ] gfx906에서 `rocm-rs` 커널 매크로 스모크가 통과한다 (최소 no-op 또는 vector add).
- [ ] P3 프로파일이 병목을 **오케스트레이션이 아니라 특정 커널**로 지목한다.
- [ ] 그 커널을 Rust로 치환했을 때의 기대 이득이 공수를 정당화한다.
- [ ] `hip-sys` / `rocm-rs` 성숙도를 착수 시점에 다시 조사했다.

**쓰지 않는 기준:** "llama-server와 차이가 없을 때만 시작".
차이가 없어도 커널이 병목이면 ROI가 있고, 차이가 있으면 먼저 스케줄러를 고쳐야 한다.

## 5. 단계별 작업

### 5.1 대상 선정

- [ ] 프로파일링으로 hot-path 특정 (후보: GEMM / attention / sampling).
- [ ] 오케스트레이션이 병목이면 P4를 열지 않고 스케줄러를 고친다.
- [ ] 하나의 커널만 골라 범위를 한정.

### 5.2 Rust→HIP 경로 확정

- [ ] gfx906에서 `#[amdgpu_global]` 스모크 (no-op / vector add).
- [ ] 스모크 실패 시: Rust에서 HIP 런타임만 호출하고 커널은 HIP C++로 두는 중간안. "순수 Rust 커널" 주장은 하지 않는다.

### 5.3 커널 구현 + 치환

- [ ] 선택한 커널을 Rust로 구현. 기존 ggml-hip과 **수치 일치** 확인.
- [ ] feature flag로 Rust 커널 ↔ 기존 FFI 커널을 전환 가능하게.

### 5.4 회귀 검증

- [ ] 치환 전후 동일 벤치. 회귀 없어야 채택.
- [ ] 정확도(출력 로짓/토큰) 일치 확인.
